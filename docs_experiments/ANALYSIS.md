## 二、结论

1. **top-k 选择在 4K 预算下饱和,不是瓶颈**:随机 anchor 零样本命中率即 99.7%、frac_qh 0.567(>随机 0.492);
   训练后(hit=1.000, frac_qh 0.586)几乎无变化。needle chunk 从来都在被选中的 32 块里。
   => single_niah 0.195 的失败发生在选中集合**内部的内容提取**(value 注意力未能聚焦 needle 数字),
   而非"检索没找到块"。这也解释了为何 anchor 训练/LoRA 对该任务零增益(0.205→0.195)。
2. **anchor 分化 = 自信但内容无差别的路由**:condH 0.69→0(lora)/0.10(anchor-only),
   anchor_load 恒 [0.5,0.5] 平衡;分化达到 spec 目标但未转化为任何选择增益。
3. **LoRA 在 LM 压力下先牺牲检索、后部分回补**:frac_qh 0.586→0.43(3000)→0.50(20000),
   rank 14.3→13.0,始终未超过零随机 anchor。=> 与"mass_lora 检索不升"自洽。
4. **预算扫描佐证**:即便 topk=4(18.5% 预算,选择真正起约束),mass 0.163 ≈ fixed0 0.170 ≈ dsa 0.177
   (9/5 sweep),anchor 打分与塌缩消融从未拉开差距。
5. **hils_lora 0.475 的优势因此不在"选块"**(两边都饱和选中),而在内容提取几何:HiLS 的选择分数
   直接是 q·landmark_key,qkvo LoRA 同时锐化了选中块内的内容注意力;MASS 的选择梯度走 anchor 旁路
   (topk 饱和 → 选择梯度弱),LoRA 只改局部/内容通路。

## 三、建议后续

- 小预算/长上下文重跑探针(topk=4/8,或 8K/16K 输入),让选择真正绑定后再评 anchor 价值;
- 直接测内容提取:answer 行对 needle token 的注意力质量(选中集合内 softmax 质量对比 hils_lora);
- 若 MASS 要证明自身,考虑把 anchor 打分与 q·k 主通路耦合(如 anchor 调制而非旁路)。
